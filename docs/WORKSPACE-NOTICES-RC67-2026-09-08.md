## Authority, scope and recovery

Account_Setup_Notice_Service is registered only when the bundled PhoneKey core loads, replacing that core's previous anonymous admin-notices callback. Through the existing PhoneKey_Bridge it reads the current actor and the unchanged pk_is_privileged, pk_admin_enrollment_complete, credential/factor helpers and native password-binding metadata. It neither updates enrollment nor changes login policy, sessions, gates, role authority or recovery. The CTA also uses the bridge to call pk_surface_login_url; it carries no account ID, credential, reset token or new redirect parameter. Actual completion still occurs through the existing protected flow.

Workspace_Notice_UI renders escaped content and the two supported priorities. Its shared CSS projects the existing Seam token defaults to a notice-local scope, including standalone technical-owner notices. Only eligible reminders enqueue the small notice stylesheet and shared primitives. There is no new JavaScript, REST route, database state, polling, AI call or visitor/PWA dependency. Each source service decides visibility; the renderer has no persistence or permission authority. Details expand with browser-native keyboard/touch behavior even when JavaScript is disabled; without styles the semantic warning, link and disclosure remain readable.

No data migration. Restoring the exact earlier package returns the previous notice presentation; it does not undo or alter completed enrollment/business setup. Prior AI/SEO rollback rules remain applicable. Key and Seam repositories, public SiteGraph/export schema, security enrollment rules and notification delivery need no changes for this presentation batch. Product Vision and maintainer policy already cover the accepted direction; a new architecture decision is unnecessary.
