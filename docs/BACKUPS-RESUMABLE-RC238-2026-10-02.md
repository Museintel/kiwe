# RC238 — Resumable native content backups

Status: accepted on the disposable lab, 2 October 2026. Native, Chrome, saved-data, retirement and public-health checks passed. Overall Backups remains partial.

Collection downloads now create encrypted sets with saved capture, full review, draft-import and relationship progress. Posts, Pages, supported Woo Products, native Post/Product categories and Bricks templates reuse the existing cipher and native record adapters. The selection freezes at start, with up to 1,000 primary records, 5,000 total including variations and 64 MiB per set. Each complete variable product must fit a 200-record/10 MiB part. Text-heavy selections use smaller parts. Inclusive creation dates retain the website timezone. This captures content over an interval, not an atomic database snapshot.

The shared dialog supports Pause and Resume. Backups → Content shows compact saved-progress cards that open that same dialog. Closing or reloading keeps the committed checkpoint and clears the passphrase; continuing requires re-entry. Every part is checked before explicit import confirmation. Imports create native drafts and keep originals; removal keeps committed drafts. A final guarded pass restores Page parents and grouped-product relationships across parts. Woo variation authority follows its new draft parent. Existing v1 `.kiwe` files remain supported; resumable downloads use `.kiwe-set`.

Actor-owned encrypted checkpoints and a private native journal stay outside the document root. OS locks exclude concurrent steps and release when a process dies. A stale step revision returns saved progress rather than advancing twice. Durable native receipts recover committed steps after transient expiry; unchanged partial records can be cleaned before retry. External edits stop automatic cleanup or duplicate creation. ZIP entries are exact, bounded, uncompressed and authenticated, and are read without extraction. Keys are never stored. Eight jobs per account and forty per website are bounded; seven-day copies remain visible and removable after expiry. Free-server-space checks do not promise hosting-account quota or inode availability. PHP ZIP is required; servers without it retain the bounded v1 path.
