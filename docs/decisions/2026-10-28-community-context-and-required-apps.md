# Community context, form identity and required Apps — 28 October 2026

Status: accepted direction; implementation and qualification in progress.

The founder extends the Comments launch with feedback-derived testimonials, identifiable forms, permanent Auth/Security Apps and contextual editing. This supersedes the manual testimonial selection step, not native comment moderation or product-rating authority. The founder explicitly authorizes the qualified final release on Dharwad, National and Ascendants and publication of Start/Seam; no additional deployment confirmation is required for this scope.

Native comments remain the only quote store. Design Context's existing content plan selects pinned, team-hearted and optional liked public feedback. Its existing `kiwe_testimonials` loop and tags remain compatible and gain source context. Every quote rechecks public target, approved ancestry, Store applicability and safe public identity; staff replies never become customer endorsements. Legacy curation migrates in explicit privileged bounded batches to native team-heart metadata. Reads never migrate. Only pages rendering testimonials carry the native LiteSpeed collection cache tag, purged on source writes; likes cannot purge every page. See [LiteSpeed's native tag/purge API](https://docs.litespeedtech.com/lscache/lscwp/api/).

Form authors use `data-kiwe-form` (a stable lowercase slug) and `data-kiwe-form-label` (a human name). Bricks owns actions, delivery and submissions. Identity is derived from saved native settings and recorded as an internal native submission field; a posted field cannot rename a form. Filters use the native page/form pair to prevent collisions. A confirmed exact native insert queues a role-derived private team notice without enquiry answers or contact details. Daily badges and both inbox presentations share existing visit and entitlement owners. Saved messages do not prove email delivery or marketing consent.

Auth and Security remain included in Core, outside the optional remote App installer. Their cards have no disable, removal or automatic-update mutation. PhoneKey's tested engine and WordPress accounts/roles/assurance remain unchanged. Settings delegate to their existing native validation/write owners, preserve untouched and secret values, and require the original capability, nonce, origin and fresh-state proof. Old settings entrances redirect after the replacement is complete; native operational records are not deleted.

Menu Edit is private and object-capability based. The native edit route and existing mandatory/optional workspace policy remain the routing owner. Public cached HTML carries no staff authority. Native editor admission rechecks the record permission.

Verify native privacy, curation revocation and migration, multiple forms, queue failures and recipient-role changes, Auth/Security denial and exact partial-save preservation, native/mandatory editing and Store-off behavior. Final source, lab, real Bricks, guest commerce, recovery, shared artifact publication and named rollout are separate evidence gates. [Completion scope](../KIWE-1-COMPLETION-2026-10-28.md).

Ordinary client Auth controls follow the existing client-administrator/context capability. Provider secrets, staff-role rules and WordPress access enforcement remain technical-owner only. Security’s ordinary severity/flood controls follow the original notification-policy capability. Native reads and mutations recheck same-origin nonce and matched route identity; Auth partial writes delegate to the unchanged PhoneKey writer, preserving untouched role matrix fields and encrypted values. Security mixed writes use the original Core sanitizer/selected writer and native policy owner. The options transaction uses next-transaction READ COMMITTED admission to reject an outer active transaction without implicitly committing it; no SESSION/GLOBAL isolation change is used ([MySQL documentation](https://dev.mysql.com/doc/refman/8.4/en/set-transaction.html)).

Native WordPress comment-query caches key only their supported arguments. Custom filtered testimonial membership therefore uses native cache_domain with the source policy, Store state and the reaction object-cache revision. Committed reactions bump the revision; public identities, role/capability changes, review/rating settings and source visibility expire only tagged testimonial pages. A public read performs no compatibility migration or option write.

Form confirmation searches from a captured native primary-key floor and matches the private random receipt, followed by exact saved identity comparison. It does not depend on a newest-twenty window, so later arrivals cannot displace the original saved record. Native Bricks duplicate rejection creates neither a new row nor a false notice. No enquiry answer, submitted contact, credential or internal receipt enters the public authoring packet. [Native Bricks action/storage authority](https://academy.bricksbuilder.io/builder/features/save-form-submissions/) and [the native storage filter](https://academy.bricksbuilder.io/developer/hooks/filters/bricks-form-save-submission-form_data/) remain the integration owners.
