# Local SEO app admission

The founder prioritizes a single Home → App → SEO activation card before the Ascendants Core upgrade, further CSS/shared-host performance work and later Ecommerce extraction. The first implementation is a bundled local app, with independently downloadable packages and their update lifecycle left to a later Apps deliverable. Dormant distributed files are not evidence of runtime execution or a completed physical plugin split.

Reuse `kiwe_seo_workspace_enabled_v1`; do not add a shadow setting. Resolve the effective state after ordinary plugins load. An active Rank Math, Yoast, AIOSEO, SEOPress or The SEO Framework owns SEO regardless of a remembered Kiwe choice. Sites without another provider default to Kiwe SEO; explicit existing off choices stay off. A muted provider-owned card explains the reviewed handover requirement and cannot activate competing output. No automatic external-plugin deactivation, import or deletion occurs.

The [complete context independence clarification](2026-10-24-complete-context-without-seo.md) applies to the entire Design Context → Site Graph/MCP → Start → Seam/Bricks authoring flow. Preserve its full schema, guided setup and existing authorized exports with the App off. Inputs remain Core even when a field is named SEO or an optional App consumes it.

Only the admitted engine constructs/registers title/canonical/social/schema output, Kiwe sitemap/News adapters, redirects, metadata handover/import, refinement and checklist workers. Core retains Design Context, the approved SEO goal, native content, provider-neutral analytics and the existing authorized per-record indexing editors. Without any SEO provider, a small Core policy preserves explicit record noindex choices in WordPress robots and native sitemap query arguments; it adds no SEO title, schema, canonical, news, redirect or analysis engine. Another active provider receives no Kiwe robots or sitemap filters. Saved metadata, defaults, queued work and AI opt-in history remain when the app is off. Already dispatched work cannot be recalled; future requests have no registered app workers.

One capability/nonce/origin/mutation-checked POST changes the existing option with stale-state and named database-lock admission. Native Home fallback uses the same writer. The legacy AI API delegates to that owner; its duplicate visible SEO master switch is removed. Reload after confirmation establishes the new hook graph. An explicit change marks native rewrites pending; the next eligible administrative lifecycle soft-flushes once after complete initialization. Visitor requests never rebuild rewrites, purge caches, call a catalogue, allocate a new job or write app state. Existing native page-cache owners purge only on the explicit app change.

WordPress documents [plugins_loaded](https://developer.wordpress.org/reference/hooks/plugins_loaded/) after ordinary plugin files and the native [taxonomy sitemap query filter](https://developer.wordpress.org/reference/hooks/wp_sitemaps_taxonomies_query_args/). Its [rewrite API](https://developer.wordpress.org/reference/functions/flush_rewrite_rules/) distinguishes a soft option refresh from writing server configuration and warns about repeated flushing. Actual WordPress and browser acceptance remains necessary beyond these source contracts.

Source/lab authorization does not authorize production. Ascendants' actual RC55.5 source/provider/data/recovery compatibility must be qualified separately with Rank Math still in charge, followed by named approval. Four existing deferred Ascendants migration outcomes, Google/MCP and Woo extraction are not completed by this local App boundary.
