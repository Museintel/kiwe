## Result and authority

The old overall-score calculation loaded all matching native content and media rows, including the legacy AI proposal job, into one PHP request. Full onboarding saves and score cron could run that calculation. RC63 removes both unbounded score queries and the legacy proposal dependency. No AI calls are involved in the checklist.

Native post/meta and relevant business-option changes signal a background refresh. Multiple signals in a request coalesce. Each worker step projects at most 25 records using ordered ID ranges against an initial maximum ID. A compact page-existence query and native identity getters supply onboarding evidence without calling the full Design Context `current()` inventory. Progress holds counters, not content copies or an ID list. Results contain fixed flags plus at most 2,048 characters of phrase metadata and 512 characters of intentional-empty metadata per row. The worker does not transfer post bodies or all metadata to PHP.

The existing technical SEO home now shows the last completed checklist, its timestamp, pending/error state and records inspected in the current scan. It has one explicit update/continue control, independent of AI permission, key or quota. It requires `manage_options`; no new client, author, product or builder permission is introduced. It reuses scoped task CSS. No new stylesheet or visitor JavaScript is added. DSA and context readers use the completed snapshot, never partial counters, and do not start jobs just by reading it. A missing score is not reported as zero percent complete. This is recorded-field completeness, not a ranking, traffic or sales prediction.

WordPress remains authoritative. The worker only reads native data. Completion atomically publishes its counters/report; it never writes post content, SEO metadata or native options belonging to another feature. All current readers use the shared snapshot getter. The old `overall_seo_report` method becomes a compatibility entry that optionally queues work and returns the last report (or an empty array); it no longer promises synchronous recalculation even if a caller supplies a profile argument. The unused onboarding report read is removed.

## Checklist method

Weights remain onboarding 20, pages 20, posts 15, products 20 and media 25. Empty scopes are inactive and their weights redistribute. Public published posts/pages/products require no password; products participate only while Woo is available at the start of that scan. Media must be an unprotected inherited attachment with no parent or a public, unprotected parent. Private/unpublished/protected parent media is excluded. Changes to a custom parent post type also signal refresh.

Content fields award 40 points for SEO title, 40 for description, 10 for excerpt and 10 for nonempty native search phrases. Empty serialized arrays no longer earn phrase points. Native duplicate metadata follows the first meta ID rather than an arbitrary MAX string. Images retain title/alt/caption/description weights of 20/40/20/20; other media uses 30/30/40 for title/caption/description. Explicit native intentional-alt evidence is recognized. Accepting an old AI proposal alone never supplies missing alt points. Metadata parsing is bounded, rejects object instantiation, and handles malformed/truncated arrays conservatively. This may lower an earlier score without any content regression. A record is called ready at 80 points; field presence does not certify its editorial quality.

The report retains the `kiwe.overall-seo-score.v1` shape for consumers and adds method `native-metadata-checklist.v2`, scan start time and inspected count. No public SiteGraph binding/schema, Key or Seam contract change is required. Other SEO plugins retain their existing frontend authority.

## Persistence, concurrency and recovery

One non-autoloaded JSON option, `kiwe_seo_checklist_v2`, owns internal schema 1, requested/completed generation tokens, one progress job, one completed snapshot, a lease, timestamps and a bounded error. It is limited to 16 KiB. Worker reads refuse oversized state before materializing it; validated writes use byte-exact CAS with at most five retries. Store callbacks never contain native queries, provider calls or other external work. Publication of the completed report and the completed generation occurs in the same CAS, preventing older workers from separately overwriting a newer report.

A 60-second lease serializes steps. An already queued lease-expiry event provides recovery if a process dies. Since checklist work only reads records, an expired page can safely replay from the last committed cursor; a late worker cannot commit over the replacement lease. This differs deliberately from RC62 paid/uncertain AI operations, which require manual recovery. Normal pages wait 15 seconds. Early/duplicate cron events cannot count the same page twice. Persistence failures leave old counters and the recovery event; read/calculation failures preserve the old report and pause for explicit retry.

Native edits during a scan change the requested generation without overwriting in-flight counters. That scan may publish a mixed-time snapshot but remains marked pending; a following scan catches the newer generation. A scan is not a transactionally frozen catalogue, nor is the displayed score real time. New IDs above the initial boundary enter a later scan; deletions and type changes do not trap the cursor. Continuous writes can keep follow-up scans pending. Periodic repair is opportunistic: an authorized context-manager admin visit initializes missing state, repairs a pending schedule, or requests an idle snapshot older than a day. It is not a perpetual timed monitor or a 24-hour freshness guarantee.

Cron scheduling depends on host/traffic and may fail. Pending state survives; the explicit technical-owner control can execute one bounded step and retry a paused scan. GET, bad nonce and denied-role actions cannot mutate or scan. The new worker uses `kiwe_refresh_seo_checklist_v2`; the old `kiwe_refresh_overall_seo_score` event now only signals this worker. No external queue service or cron daemon is added. Database availability, clock reversal, corruption and contention fail closed; do not delete state as a routine recovery shortcut.

The previous `kiwe_overall_seo_report_v1` option is retained as a read-only fallback until a new report exists and is labelled as an earlier method in the technical UI. It is no longer a live mirror. Rollback to older source will read its old snapshot and reactivate the former full-library scoring path; it does not inherit the RC63 performance behavior. RC62 job and RC61 allowance downgrade precautions still apply independently. Preserve state and the previous package when preparing grouped lab installation.

## Practical limits and acceptance

The bound is on returned rows, retained progress and projected metadata, not a universal database-time or memory guarantee. Database expressions still inspect native field contents, so huge individual records, metadata indexes, plugins and host load affect cost. Existing Design Context inventories outside this score path remain separate performance work. No claim of measured production speed, full PHP 8.2/MySQL acceptance or browser visual acceptance is made by this local batch.

The deterministic fixture executes the actual worker, score source, profile evidence/getter and permission handlers with fake WordPress/database operations. It checks a 10,000-record scan, Woo present/absent, stale/concurrent edits, empty/private/protected content, first-row metadata semantics via query contracts, lease recovery/fencing, failed native reads/state writes, corrupt state, clock reversal, cron failure, compatibility reads and rendered progress. SQL shape assertions are not actual MySQL execution or proof of query plans. No network/provider is used. Local baseline, PHP syntax and maintained-link checks are grouped after the build; final evidence is appended below.

The next acceptance pass must exercise actual PHP 8.2+ SQL and CAS concurrency, native event invalidation, WordPress cron/manual recovery, RC59–RC62 request/token/permission/jobs and scoped mobile/keyboard behavior. Fix concrete acceptance blockers within that pass and move to dashboard work; do not add deferred SEO features under the acceptance label.
