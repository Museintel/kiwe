The founder's outcome is beauty, innovation, ease of use and speed on phone, tablet and desktop. DSA screens and the client workspace should feel related: coherent typography, spacing, surfaces, iconography, motion, navigation, cards, forms and feedback. A separately hosted dashboard is an available implementation choice, not the product requirement. A remembered research idea does not replace the active engineering sequence.

CSS can deliver responsive appearance. JavaScript can deliver stateful interaction. REST supplies structured reads/writes; it neither makes a screen beautiful nor requires moving it to another host. WordPress supports cookie-authenticated API calls inside a logged-in WordPress application, with REST nonces and operation capabilities. Custom endpoints also require permission callbacks and argument validation. These documented mechanisms support an app workspace served by the site's existing WordPress installation. [WordPress REST authentication](https://developer.wordpress.org/rest-api/using-the-rest-api/authentication/), [custom endpoint permissions and arguments](https://developer.wordpress.org/rest-api/extending-the-rest-api/adding-custom-endpoints/).

Updated engineering recommendation: keep the client workspace on the site's origin and build a dedicated React shell around existing native domain services. Its final client navigation has no permanent WordPress sidebar or toolbar; internal task screens, native data adapters and capability-derived tiles define the app. This preserves the single-site shared-host deployment and session model. Keep native editors and extension routes available where their specialized workflows are still required. A later separately hosted or federated workspace needs evidence that its gains justify additional authentication, CORS, deployment, compatibility and outage handling. That recommendation is an architectural inference, not a WordPress platform restriction.

Share design primitives and interaction contracts across DSA and administration, while retaining audience permissions and route-specific loading. The first implementation step is to inventory existing DSA/task tokens and components, choose a canonical primitive source, and generate or import only what each surface needs. Public DSA must not download the administrative application to share a card or button. Client private data and API responses must never enter public page/PWA caches. A shared visual language does not mean shared private state or replacing the client's front-end art direction.

Each task has one editing home and uses the native WordPress/WooCommerce getter, validation, writer and capability already identified in [Client Workspace Tasks](CLIENT-WORKSPACE-TASKS.md). REST adapters should call those services rather than create competing write paths or shadow settings. Server authorization, object permissions, stale-edit checks and native readback remain required. Persistent credentials must not be embedded in browser bundles. Do not add an API endpoint for a flow that works better as a small accessible form.

App behavior includes navigation history/deep links, loading/empty/error/saved states, clear pending writes, cancel/retry semantics, keyboard and focus behavior, reduced motion, meaningful touch targets and layouts that reflow. Optimistic UI must not report an unconfirmed native write as saved. Animation must not delay a ready destination. Offline administration requires an explicit conflict/authentication design; do not silently queue consequential writes or imply offline capability because the visitor site has a PWA.

Measure loaded code, requests, server time, interaction responsiveness and cold/warm behavior separately for public DSA and authenticated workspace on the same lab/fixture. Define measured budgets before selecting a large client framework or router. Verify at phone/tablet/desktop sizes with keyboard and reduced motion. Source-only assertions are not visual acceptance. Current scoped task CSS is an intermediate implementation, not proof that the entire dashboard meets this contract.
