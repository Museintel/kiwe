## What this build delivers

One small request and one large AI batch should not consume an identical work allowance. Kiwe now reserves estimated token units as well as one request attempt before every direct HTTP attempt or WordPress AI Client invocation. Valid Gemini response usage settles the reservation and releases unused units, allowing the website to use its allowance more efficiently. Failed, missing, malformed or unsupported usage retains the full estimate. Request attempts are never refunded.

Owner controls are added to the existing Website AI allowance area, beside the original request ceilings. The new native fields are `dsa_settings.ai.token_allowance.minute/day/month`; there is no second client budget editor. Missing submitted fields preserve prior values. Zero pauses generation; invalid submitted values normalize to zero. Defaults are 100,000 per minute, 300,000 per day and 3,000,000 per month; each field is bounded to one billion units. These are Kiwe defaults, not advertised provider quotas, verified free-tier capacity or a spending limit.

The client AI assistance screen shows **used or reserved token units**, remaining units and when tracking began. Earlier requests are explicitly excluded from token history. The screen exposes no receipt identifiers, provider payloads, secrets or writable technical limits. Existing scoped responsive cards and stylesheet are reused. No visitor asset, new stylesheet, cron, custom table or background service is added.

## Estimation, provider reporting and practical limits

The estimate is the UTF-8 byte length of the encoded outbound payload, plus the configured output limit (200–12,000), plus 8,192 units of reasoning/framing headroom. JSON schema and escaping therefore count. Invalid JSON or a payload above 250,000 encoded bytes fails before reservation. This is a conservative heuristic, not an exact tokenizer or a mathematical upper bound for every model. It deliberately avoids a second network call for token counting. A packet larger than any complete window gets an actionable failure with no automatic retry time; waiting cannot make it fit.

Google documents input/output/thinking/total usage on Interactions responses, and output pricing can include thinking. Kiwe's parser counts reasoning separately, does not add cached input twice, and requires nonnegative integer fields and a consistent positive total before releasing anything. GenerateContent's `usageMetadata` has a separate adapter. Tool usage, if unexpectedly present, is accounted conservatively, although this transport does not request provider tools. [Token guide](https://ai.google.dev/gemini-api/docs/tokens), [Interactions reference](https://ai.google.dev/api/interactions-api), [pricing](https://ai.google.dev/gemini-api/docs/pricing), [GenerateContent response](https://ai.google.dev/api/generate-content#UsageMetadata).

Only Gemini adapters settle reported usage in this build. OpenAI-compatible, Groq, xAI and WordPress AI Client calls keep their estimates because their usage contracts have not been accepted here. The WordPress wrapper returns text and does not expose a certified count of underlying retries or provider consumption; its reservation covers the Kiwe invocation. No new provider, fallback, model default or endpoint is selected. The existing diagnostic characters-divided-by-four estimate is not used to authorize spending.

When reported units exceed the reservation, Kiwe charges the larger amount and pauses shared AI for at least one hour, preserving any longer existing provider cooldown. The completed output may still be returned. Remaining units clamp to zero instead of showing a negative allowance. An in-flight request can therefore exceed the heuristic reservation; other already sent requests cannot be cancelled. Future hard monetary controls need a verified tokenizer/output/reasoning/attempt contract, model pricing/version handling and billing-policy integration. RC61 must not be sold as a guaranteed money cap or proof of free-only billing.

## Atomic state and recovery

The existing non-autoloaded `kiwe_ai_allowance_v1` row stays the single authority. Its internal schema becomes 2, adding token counters, tracking start and at most 64 pending receipts. Request and token balances change in one compare-and-swap write; a consumer denied by either allowance cannot leave a partial reservation of the other. Receipt IDs contain 128 random bits and are internal, with only reservation time and units stored. No prompt, model response, key, user or object record is stored in this ledger.

Settlement checks the receipt and updates balances/removes the receipt in one CAS. A duplicate, forged unknown or expired receipt cannot refund units. Reservations are assigned to their starting UTC windows; a late response never refunds the next minute/day/month. Receipts expire after five minutes, while their charged estimate remains. Expiry frees bookkeeping space, not allowance. Pruning happens on an eventual write; status is read-only. Exhausted receipt capacity and repeated contention fail closed. Invalid counters, impossible pending balances, database failures and backwards clocks retain the existing fail-closed behavior. There is no database lock held across HTTP.

Schema 1 is validated before lazy conversion. Request counters and provider holds are preserved; earlier token usage is not invented. Conversion and the first reservation share one CAS write. Tracking starts at that first token reservation. Read-only status does not rewrite the ledger. Accounting is forward-looking from RC61, so the first partial month does not claim to include pre-upgrade tokens.

Rollback requires a complete matching loader/package pair. **RC59/RC60 reject a schema-2 ledger and pause AI**; ordinary website functions remain independent. Do not delete the ledger to make rollback resume inference. Any downgrade migration must preserve request/cooldown state and explicitly account for loss of token enforcement. Database restoration or external ledger deletion can restore allowance and remains outside this local protection; the future backup product must reconcile it. Keys and token ceilings do not reset counters.

See the [accepted settlement decision](decisions/2026-09-06-ai-token-settlement.md).
