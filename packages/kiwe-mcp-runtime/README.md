`composer.lock` pins WordPress MCP Adapter0.7.1, PHP MCP Schema0.2.0 and Jetpack Autoloader6.0.3. `tools/mcp/build-runtime-vendor.cjs` verifies the reviewed lock and deterministically isolates dependency namespaces, hooks and constants in the optional App. Its private autoloader admits only the two owned dependency prefixes. `--check` compares every transformed byte and the recorded inventory against the original lock. Keep the dependency inventory and licences. No vendor autoloader runs on ordinary visitor requests. The independent Core profile excludes all MCP engines, dependencies and UI assets.

The website manager installs/enables MCP through the native Apps platform; that explicit action prepares private connection storage. Each authorized staff member then adds the remote HTTP address shown by Kiwe → Apps → MCP to their own AI application. Native OAuth/PKCE consent binds the requesting client, browser, person, exact resource and finite scopes. No WordPress application password, AI API key or bearer token is pasted into chat. The first release supports individual HTTPS WordPress7.1+/PHP8.2+ installations. Actual client/protocol and hosting compatibility require the acceptance receipts; source tests alone are insufficient.

Connection records are private delegated-access state, not a second business-data store. Access credentials expire in fifteen minutes; consented rotating refresh is bounded to fourteen days. Native disconnect/App Off/deactivation invalidates authority. Native uninstall deletes only the MCP connection table/options; other website data/settings remain. Recovering removed code requires new connections. Keep all test credentials/configuration outside source and protect them after qualification.

Future Apps register trusted code via Core's `DSA\Apps\MCP_Provider_Contract::register`. The factory returns local typed operations and setup readiness on explicit discovery. Use App-scoped IDs/scopes, closed typed input/output schemas, discoverPermission, native object permission, explicit effect/approval and accessVersion. Setup needs refer to existing Design Context fields. New/changed operation fingerprints never inherit earlier consent. Google/Meta linking, provider tokens, messaging consent and spend permissions remain owned by those Apps. There is no arbitrary REST, SQL, PHP, HTTP or option/meta escape hatch.
