# Design Context: the ongoing business workspace

10 September 2026. **Accepted founder direction; source inventory and local React preview extension.** The founder explicitly approves the tile workspace's appearance. Preserve that visual language while covering the whole existing Design Context and daily business workflows. Logo editing is the first interaction example, not the boundary of the product. Local/lab runtime remains RC82; Ascendants remains verified RC55.4. This change makes no native, schema, capability, package or live-site changes.

## Product contract

The client can revisit the workspace every day to write, sell, organize people and services, change business facts and control the website. Onboarding is an entry into those same editing homes. Returning clients must not repeat a setup wizard to make one change. Identity controls belong together: name, tagline, main logo, adjacent optional dark-background logo and site icon. A business header provides another entry into that same task.

Every existing control retains its WordPress, WooCommerce or existing Kiwe authority. Multiple entry points open the same form; they do not create separate copies of a setting. Related actions stay next to their subject: category rename/move/menu/indexing actions beside the category; team selection and public title beside the person; search appearance beside the post, page or product. Summaries link to these homes. Advanced choices expand within the relevant task rather than appearing on another settings island.

The full workspace, the AI brief and published website information are related but distinct views:

| View | Inclusion rule | Consumer |
| --- | --- | --- |
| Operational workspace | Records/actions permitted for the current person | Client, editor, author, approved contributor or store staff |
| Design Context for design/AI | Explicit business facts, page intentions and selected evidence; purpose-limited export | Designer, Seam/SiteGraph and permitted AI features |
| Public website/search facts | Approved public values and explicitly selected content, respecting visibility and SEO ownership | Bricks bindings, DSA, rendered metadata, structured data and sitemaps |

Uploading a file, registering a user or receiving a review does not automatically add it to the design brief. Team selection does not change account roles. Public contact is not the account's private login/contact data. AI/provider credentials, drafts, private notes, private users and operational records must not leak into public metadata or the visitor bootstrap.

## Save once, update connected uses

1. Load the current authoritative values, permissible actions and an expected-state token; retain drafts while navigating sections.
2. Validate through the native owner, enforce CSRF/session/capability/object checks and reject stale or unauthorized changes. A role name in a selector is not authorization.
3. Persist only the task's changed supported fields through the native writer. Return an actual readback and update the client cache from it; failed saves retain the draft.
4. Use existing WordPress/Woo/Kiwe invalidation hooks. Verify affected public caches and actual Bricks/DSA bindings without a global purge on every keystroke. Never infer success from the sample header changing.
5. Show confirmed connected uses or an actionable missing binding. Preserve explicit local overrides. Future usage counts require a real binding inventory; the preview's usage chips are illustrative.

The grouped native acceptance must cover changes from Kiwe and from the original WordPress controls, logo replacement/removal/fallback, favicon clearing, public readback after cache handling, SEO-plugin active/inactive behavior and role/stale/session failures. No blanket write-through to arbitrary theme text or generated HTML. Public schema must not include the private profile export.

Search engines consume public output, not the client's private dashboard JSON. Google documents [site-name structured data](https://developers.google.com/search/docs/appearance/site-names) and [organization information](https://developers.google.com/search/docs/appearance/structured-data/organization) as ways to help interpret a website's identity. Search display can lag behind a site edit because recrawling/processing takes time. A local completeness score is not a ranking guarantee. SEO replacement must separately verify existing Rank Math ownership/migration; this preview does not replace it.
