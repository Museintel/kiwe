# Ecommerce surface checklist

Use this with every commerce brief, including a request for just one page. Record `authoring/ecommerce-coverage.json`: each applicable row below has a disposition (`produced`, `existing-native`, `out-of-scope`, `not-applicable` or `blocked`), the responsible route/template/DSA, and evidence. A homepage-only request leaves other surfaces out of scope; it must not silently claim a complete store. Existing native endpoints can satisfy a row without a duplicate static page. SiteGraph or a native inspection must establish existing assignments and conditions; a filename or a guessed slug is not evidence.

| Surface | Required behavior / native owner |
| --- | --- |
| Home | Current-record heroes, real category destinations, responsive content and active actions. |
| Shop | Real catalogue query, usable sorting/filter/empty states. Avoid duplicating a shared header Search DSA field. |
| Product category / applicable tag archive | Current queried term, correct product query, shared category rail with a readable active state and working All products link. |
| Single product | Actual product/variant, pack information when supplied, price, availability, native purchase, wishlist, contextual Reviews and Share icons, and a configured WhatsApp Chat button beside Add to cart. |
| Cart with items / empty cart | Native totals/fees/tax/shipping policy and correct empty/recovery states; Kiwe Cart DSA plus the configured native fallback can fulfil this. |
| Checkout | Configured Woo endpoint, guest/account policy, required fields, errors, one native customer-details/order/payment owner. |
| Pay for an existing order | Native `wc_form_pay`, native order table/payment elements, authorized current order/key and real gateway/nonce; expired, already-paid and denied cases. A generic Checkout template is not this endpoint. |
| Order received / Thank you | Native `wc_thankyou`, real authorized order and payment status, failed/pending/received distinctions, native gateway hooks/order details. Never show a static payment-success claim or invent a receipt/order. |
| Account / orders / order details | Existing PhoneKey/Profile and Woo ownership; address, recovery, payment methods and downloads when applicable. Do not duplicate authentication. |
| Header / footer | Shared search, cart, approved notifications, real links and attributed iPhone/Android install actions. |
| Saved items | Product wishlist; post bookmarks when editorial content exists. Shared Kiwe state owns badges/selection. |
| Contact / enquiry | Stable form identity and human label; native saved submissions, deliberate email recipient binding and truthful delivery status. No collected real enquiry in a raw preview. |
| About | Grounded business/owner story and actual approved imagery. |
| Policies | Owner-approved privacy, terms, delivery, cancellation, refunds/returns and food/product disclosures as applicable. Preserve a preferred existing accordion design; do not invent legal promises. |
| Editorial archive / single post | Only when present/in scope. Current post, bookmark, contextual Comments and Share icons; categories/tags use native destinations. |
| Search / no results / 404 | Working DSA/native search and useful recovery paths, without duplicated indexes. |

Every single post and single product needs a visible, accessible icon button in the reading/purchase action area. Use the exported shared Comments icon and `data-dsa-open-module="comments"` with `data-dsa-discussion-id="current"`. Its label is Comments on a post and Reviews on a product. Declare the corresponding launcher stitch with SiteGraph authority and `discussionTarget: "current"`; use the current record, never a preview product ID on every page. The shared handler owns the count and screen. The Dock is optional and cannot substitute for these in-content controls. Closed native comments/reviews remain readable according to native policy; do not silently change that policy. A website-feedback launcher uses `site` only when configured and supported.

Every single product and single post also needs an accessible **Share icon in its own action area**: `data-kiwe-share="native"` and the exported `{kiwe_icon_share}` (or the proven older `{kiwe_icon_share_2}` equivalent). On a single product, place a **WhatsApp Chat button immediately beside the native Add to cart control** when the current target lists WhatsApp in `kiwe.links.configuredEnquiries`. Use `data-kiwe-chat="whatsapp"`, `{kiwe_icon_whatsapp}` and a clear label such as “Ask on WhatsApp”. Keep quantity/variation validation, cart submission and the chat button as separate sibling actions; Chat must be `type="button"` if it is inside a purchase form. It opens Kiwe's enquiry DSA before the configured conversation, using the current public product title as the editable message. Do not bypass the form with a hardcoded business `wa.me` link, nest a button inside Add to cart, invent a phone number or add a custom click script. Missing WhatsApp configuration is a reported capability gap, never permission to change the business contact. Refer to `contracts/links.md` for current/loop subject rules, strict compiler launcher stitches and private form semantics. The Dock alone does not satisfy these in-content requirements.

At conversion, verify the actual template type and native selection conditions, not only generated filenames. During lab acceptance check guest/signed-in/denied/error contexts without a real payment or live-customer message. Static preview placeholders are explicitly local demonstrations and disappear inside their native replacement owner. Native saved-form success does not prove email delivery.

Responsive acceptance checks the complete native page with its installed Header and Footer, not just each isolated source file. If shared templates retain a copy of the project's stylesheet, a changed rule must have the same owner/version in every rendered copy. A correct page-local rule can otherwise be overridden by an older Footer copy. Check intermediate media boundaries/interiors as well as desktop and phone; record actual grid tracks and readable controls even when document overflow is zero. Repair the exact source or native style owners, without adding a global reset or redesigning intentional layouts.
