# /ideate

Start with discovery, not a fixed questionnaire. Inspect every supplied file before asking anything and determine which lane is proven by the evidence: a new website, a redesign of an existing website, or enhancement/expansion of an existing HTML/CSS/JS project. State the detected lane and ask only for missing decisions that materially change the result. Never ask again for facts already supplied by the project, SiteGraph or its embedded Design Context.

Before designing, classify SiteGraph as `required`, `beneficial`, or `not-needed` and explain the evidence. SiteGraph is required when the requested result must use or preserve real site identity, owner decisions, media, products, posts, services, menus, taxonomies, custom fields, commerce data, or future dynamic-binding intent that the supplied files do not prove completely. It is beneficial but optional for an ungrounded concept that may use honest placeholders. It is not needed when the approved supplied project is self-contained and the requested work neither introduces nor changes site-owned facts. If required evidence is absent, stop before recreation and request exactly one safe SiteGraph handoff.

Choose the safest SiteGraph connection the participating AI can actually use. Prefer an already connected read-only SiteGraph tool or MCP resource; otherwise use a scoped, expiring task-capsule/API connection; otherwise request an attached current SiteGraph export. Do not pretend an unavailable connector worked, ask the user to choose technical transport, request a broad permanent key, or paste secrets into project output. Explain the one action required only when no safe connection is available.

Inventory approved source pages, assets, references and existing-site evidence before proposing work. Existing Design Context is authoritative for business facts and owner-locked brand values; SiteGraph design content supplies real media, products, posts, taxonomies, custom content and public identity. Distinguish read-only owner facts from AI-writable suggestions.

When SiteGraph is present, report **Design Context coverage before changing any file**. Use `seamDesignContext.scores.designContextStrength` as the authoritative percentage when supplied. Otherwise calculate coverage—not subjective design quality—using this evidence rubric: identity 15%, audience and goal 10%, brand preferences 15%, public contact and localization 10%, about/founder/team 15%, pages/services/content plan 10%, commerce and product context 15%, and approved resources/media 10%. Exclude a genuinely irrelevant section and redistribute its weight proportionally; never award points for guessed values or placeholders. Show the percentage, covered sections, material gaps, locked owner facts, preserved owner preferences, AI-writable gaps, and the SiteGraph/context hash when available. Emit the same result as `ideate/kiwe-ideate-discovery.json` using schema `kiwe.ideate-discovery.v2`. If SiteGraph is not needed, record coverage as `not-applicable` rather than fabricating a number.

Do not apply Seam Framework, Bricks structures or a SEAM house style. Do not flatten unusual but intentional art direction into a component library. Keep corrections conversational until the user accepts the result.

Return a complete browser-runnable HTML/CSS/JS project appropriate to the detected lane: create a coherent new project, redesign the approved existing site, or revise the supplied source in place. For an accepted supplied project, "recreate" means preserve its visual composition, responsive behavior, content hierarchy and JavaScript unless the user explicitly asks for a redesign; apply Design Context as grounded content, media and functional intent without imposing a new design language. Include every required local asset and `assets/asset-manifest.json`, recording provenance and intended WordPress Media use. Preserve semantic regions and add stable `data-seam-role` markers only when they clarify meaning without changing presentation. Mark dynamic intent such as product title, price, media, contact data or repeated collections when SiteGraph proves the binding. Never invent IDs, fields, products or site facts.
