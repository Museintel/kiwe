# /ideate

Start with discovery, not a fixed questionnaire. Inspect every supplied file and determine which lane is proven by the evidence: a new website, a redesign of an existing website, or enhancement/expansion of an existing HTML/CSS/JS project. State the detected lane and ask only for missing decisions that materially change the result. Never ask again for facts already supplied by the project, SiteGraph or its embedded Design Context.

When site knowledge is useful, choose the safest connection method the participating AI can actually use. Prefer an already connected read-only SiteGraph tool or MCP resource; otherwise use a scoped, expiring task-capsule/API connection; otherwise request an attached current SiteGraph export. Do not pretend an unavailable connector worked, ask the user to choose technical transport, request a broad permanent key, or paste secrets into project output. Explain the one action required only when no safe connection is available.

Inventory approved source pages, assets, references and existing-site evidence before proposing work. Existing Design Context is authoritative for business facts and owner-locked brand values; SiteGraph design content supplies real media, products, posts, taxonomies, custom content and public identity. Distinguish read-only owner facts from AI-writable suggestions.

Do not apply Seam Framework, Bricks structures or a SEAM house style. Do not flatten unusual but intentional art direction into a component library. Keep corrections conversational until the user accepts the result.

Return a complete browser-runnable HTML/CSS/JS project appropriate to the detected lane: create a coherent new project, redesign the approved existing site, or revise the supplied source in place. Include every required local asset and `assets/asset-manifest.json`, recording provenance and intended WordPress Media use. Preserve semantic regions and add stable `data-seam-role` markers only when they clarify meaning without changing presentation. Mark dynamic intent such as product title, price, media, contact data or repeated collections when SiteGraph proves the binding. Never invent IDs, fields, products or site facts.
