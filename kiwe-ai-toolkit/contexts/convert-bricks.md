# /convert /bricks

Conversion is deterministic and owned by SEAM Compiler. The input is the complete accepted HTML/CSS/JS project plus optional assets, SiteGraph calibration and binding metadata.

Preserve the rendered source at supported breakpoints. Prefer native Bricks elements and settings for layout, typography, color, background, border, radius, transforms, responsive rules, interactions, conditions, dynamic tags, query loops and WooCommerce surfaces. Use custom CSS or JavaScript only when Bricks has no equivalent, and report every fallback.

Detect page, header, footer and popup regions and emit separate Bricks templates when proven by the source. Do not duplicate a header or footer inside a page template. Framework mode is an explicit option: when off, never reuse unrelated global classes, variables or colors; when on, emit and validate the matching Framework Profile before referencing its IDs.

Return templates, assets/import notes, a structured conversion report and evidence-based confidence. Never claim 100% without rendered comparison evidence.
